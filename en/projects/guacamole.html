Apache Guacamole remote-access gateway

AnyDesk replaced with a containerised web gateway whose access rights are managed entirely from Active Directory.

PROJECT CARDBASTION

Context
Multi-site company
Version
Apache Guacamole 1.6.0
Hosting
Docker Compose · DMZ
Identity
LDAPS (Active Directory) + TOTP
Deliverables
Operations procedure + guide

Context

Remote access to servers and workstations relied on AnyDesk. The goal: a single entry point in the browser, with no client to install, authentication against the company directory, multi-factor authentication and rights granted per scope.

Architecture

Three containers on a DMZ server, with the directory as the source of truth.

Access model

One group in the directory, one group with the same name in Guacamole.

Each scope (RDS servers, a workshop's equipment…) maps to an AD security group named GRP-GUAC-<SCOPE> and to a Guacamole group with exactly the same name. The AD group holds the people, the Guacamole group holds the rights on the machines.

Day to day, everything happens in the Active Directory console: adding someone to the group opens the machines to them, removing them closes access. A leaver processed in the directory automatically loses gateway access.

Break-glass access

One admin group was deliberately kept local, with no counterpart in the directory. If Active Directory or the LDAPS link goes down, it is the only way left into the gateway.

Challenges

Silent traps, identified then documented for whoever comes next.

Deletion bug in 1.6.0

Deleting a group from the interface returns "Unexpected error": the JDBC extension builds an SQL query missing an AND operator. Deletion is therefore done in the database, after a backup, by ID, with a final check of the related tables.

Invisible tree

Allowing a connection is not enough: every parent folder must be allowed too, and they are not ticked automatically. Otherwise the user signs in and sees nothing, with no error message.

Wrong directory queried

The MySQL extension loads before LDAP: an account that also exists locally never queries the directory. Troubleshooting therefore starts by checking for authenticated by "ldap" in the logs.

Failures without errors

A group name differing by one capital letter or a space, or a deletion by name with an accented character: the operation "succeeds" and does nothing. Hence the rules: copy-paste names and delete by ID.

Operations

  • Backup Weekly automated backup via cron, plus a database export before any manual change.
  • Troubleshooting A four-step checklist, in order, for the "user signs in but sees nothing" case.
  • Logs Debug mode used only for troubleshooting and switched off straight after: it writes directory contents to the logs.
  • To watch Expiry dates of the LDAPS certificates and the root authority: an expired certificate cuts authentication without warning.
  • Next step Move the GRP-GUAC-* groups to a dedicated sub-OU so each sign-in no longer reads every group in the domain.

Two documents delivered: a formal operations procedure and a simplified guide for the team. When they were written (09/2026), the RDS servers group and the break-glass access were in place; the other scopes were planned.
