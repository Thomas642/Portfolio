Automated workstation deployment server

Technicians prepared every workstation by hand before installing it at a pharmacy. I built a WDS + MDT server on reclaimed hardware: a workstation plugged into the bench boots from the network and comes out with its system, drivers and software.

Context

A daily task, done entirely by hand.

Smart Rx develops and installs IT tools for pharmacies: pharmacy management software, workstations, servers, networking, video surveillance. Before each installation, the branch's technicians prepare the workstations. This was done one machine at a time, with no automation server.

  • TimeAbout 30 minutes per workstation, with a technician tied up from start to finish.
  • ErrorsManual, repetitive configuration, so steps could be missed.
  • InconsistencyPreparation that varied with the technician doing it.
  • AvailabilityLess time for support, installations and preparing other equipment.

Architecture

A server with two network cards, between the company network and the deployment bench.

Deploying a workstation

The technician only steps in at the start: the rest runs on its own.

  1. TechnicianNetwork bootThe workstation is plugged into the bench and booted from the network (PXE).
  2. AutomaticIP addressDHCP hands out an address and points to the boot server (options 060 and 066) and the gateway (003).
  3. AutomaticBoot imageWDS sends the LiteTouch Windows PE boot image generated by MDT.
  4. AutomaticConnectionBootstrap.ini provides the DeploymentShare$ path and the access account: no credentials to type.
  5. TechnicianMDT wizardThe technician picks the task sequence for the workstation model; the other questions are hidden by CustomSettings.ini.
  6. AutomaticMasterThe sequence applies the model's image: system, drivers, applications and settings.

CustomSettings.ini · rules

[Default]
OSInstall=Y
SkipCapture=YES
SkipAdminPassword=YES
SkipProductKey=YES
SkipComputerBackup=YES
SkipBitLocker=YES
SkipUserData=YES
SkipMoveData=YES

What these rules skip

  • choosing the administrator password
  • capturing an image of the workstation
  • the Windows product key prompt
  • the backup before deployment
  • enabling BitLocker
  • user data migration

Capturing the masters

The main challenge of the project.

A master is the reference image of a workstation model: Windows up to date, applications installed, settings done. I first inventoried the models used at customer sites, then prepared one workstation of each model.

Capture through MDT failed every time on these workstations, probably because of their BIOS settings. So I built a Windows PE USB key with the ADK (copype, MakeWinPEMedia) and captured each workstation with DISM, then imported the images into MDT.

Capture from Windows PE

Dism /Capture-Image
  /ImageFile:"C:\WIMFiles\MonImage.wim"
  /CaptureDir:C:
  /Name:"Windows 10"
  /Compress:max

Lesson learned My initial schedule covered 8 weeks and left out many intermediate steps. I rebuilt it along the way to match reality.

Results

Measured on the time the technician spends at the workstation.

In production

Put into production on 17 February after sign-off with the technicians, the server is used daily by the team.

Testing

Connectivity checked with ping, a deployment on each workstation model, then a real-conditions run with 7 machines in parallel.

Cost

No purchases: reclaimed server and switches. Measured consumption of 8.4 kWh per day, or €45.36 of energy per month.

Operations

A server that maintains itself before the technicians arrive.

  1. 04:30 · every 2 days

    Backup cleanup

    A batch script deletes the old backup: the 500 GB disk can only hold two.

  2. 05:00 · daily

    Full server backup

    Windows Server Backup to a dedicated disk: the whole server can be restored.

  3. 07:30 · daily

    Scheduled restart

    shutdown /r /f /t 60: applies pending updates and restarts services.

  4. 08:00

    Technicians arrive

    The server is ready for the day.

Follow-up

Regular checks for the rest of my degree: deployment errors, server updates, masters kept current.
