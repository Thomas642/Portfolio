Context

A "family" is a group of players on the LYG DarkRP game server. Keeping track of it (members, ranks, recruitment, sanctions, group life) was done in a Google Sheets workbook fed by a script, and an older tool, FamilyTracker, already sat on the subdomain.

The goal: a single, collaborative tool, fed automatically by the game server API, hosted on my VPS alongside the services already running there.

Architecture

Everything runs on a single VPS, without Docker, using standard Linux building blocks.

Approach

Document, check what is really there, then switch over in reversible steps.

  1. Scoping

    Documentation before code

    Technical plan, database schema, API integration, deployment and authentication principles, written and versioned in the repository.

  2. 05/2026

    Audit of the actual VPS

    Versions recorded (Ubuntu 26.04, Node 22, Nginx 1.28), along with the sites already hosted and the existing certificate. The plan's assumptions were corrected accordingly.

  3. Phases A → E

    Set-up in independent phases

    PostgreSQL, package manager, systemd service with a holding page, Nginx vhost prepared but inactive, then the switch-over. Each phase can be validated on its own.

  4. Switch-over

    Reversible replacement of the old tool

    Existing configuration backed up, then an Nginx symbolic link swapped. The old tool is not deleted: rolling back takes a single command.

  5. Iterations

    Core first, then features

    First Steam sign-in, member sync, profiles and the overview. Then recruitment and interviews, sanctions, polls, events, meetings, notifications, audit log and health page.

Operations

The choices that keep the service running day to day.

Sharing the VPS

The server already hosts other sites. No Docker for Bako, pnpm through corepack to leave the system Node untouched, a dedicated Nginx vhost and the existing Let's Encrypt certificate reused.

Sync

A systemd timer every 15 minutes, matched to the API limit (100 requests per 15 min). If the API goes down, the site serves the last known data and shows a banner.

Backups

A compressed pg_dump every day at 04:00, rotation over 14 backups, restore procedure documented in the script.

CI / CD

Lint, types, Vitest tests and build on every pull request. On every merge to main, deployment over SSH: align on main, migrations, build, service restart.

Monitoring

A /healthz check endpoint and an admin-only health page: live checks of the API and the database, plus periodic readings kept over time.

Access

Only the home page and the recruitment page are public. Everything else requires a Steam sign-in, with roles, and is not indexed by search engines.

Challenges

API rate limit

With 100 requests per 15-minute window, a sync never uses the whole budget. Data is cached and every sync is timestamped.

Hardened install

On the VPS, pnpm deliberately refuses to run some build scripts and returns an error. The deployment script tolerates that case only; build and restart remain blocking.

Results

  • Live BAKO replaced the old tool on famille.gameone-val.com (opens in a new tab), with rollback still possible.
  • Automated Every merge to main is tested then deployed with no manual step.
  • Backed up The database is backed up daily and the restore procedure is documented.
